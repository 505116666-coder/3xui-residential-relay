# 维护与排查

日常安装请看[项目首页](../README.md)。这里供遇到问题或维护旧部署时查阅。

## 故障隔离与检查

- 两个节点使用不同端口、UUID 和入口标签。
- 默认未匹配流量走服务器直连，新增普通入站可直接使用；住宅入站 TCP/UDP 显式绑定住宅 SOCKS5，连接失败不回退直连。
- 不添加负载均衡、自动切换和直连兜底。
- 住宅节点测试使用 `socks5h`，域名交给住宅代理解析；服务器路由采用 `AsIs`，关闭嗅探重写。
- 住宅 SOCKS5 出站直接填写代理商域名/IP、端口和认证信息，全部可在面板管理。没有额外本机转发服务。
- 安装验收会临时把住宅上游指向本机不可连接端口，验证住宅请求失败、直连节点正常，并在 `finally` 中恢复。若恢复失败或安装被中断，面板/Xray 停止，不输出成功结果。强制断电或 `kill -9` 无法执行清理，此时用 `--resume` 恢复原配置后重测。

部署结束后检查：

```bash
python3 /root/3xui-dual/manager.py --check
```

此命令不注入故障，会实际连接所有由本脚本管理的 VLESS/REALITY 入口并检查出口。路由被手动修改时，它可能拒绝验收；它不会把你的修改自动改回去。

**本机协议测试不能证明公网入口已放行。**最后必须用自己的电脑/手机分别导入两条链接，访问 IP 查询网站验证出口。使用支持的较新客户端，关闭 Mux。住宅模式应选全局代理或明确覆盖目标应用，配置远端 DNS/DoH；客户端自己的直连规则、本地 DNS、未接管的应用流量不受服务器脚本控制。

无需填写住宅 IP 是否轮换；两次出口不同不会直接判定失败，验收结合路由检查和故障注入结果。脚本只验证出口地址，不验证地理位置、ASN 或“住宅”标签真实性。

## HTTPS 自动续期

IP 证书约 6 天有效。脚本把续期周期设为约 2 天，每 12 小时运行检查（含随机延迟），重启面板使证书生效，并检查证书是否至少还剩 48 小时。ACME 服务端的续期建议也可能影响实际续期时间。

```bash
systemctl status 3xui-dual-renew.timer
journalctl -u 3xui-dual-renew.service --no-pager -n 60
systemctl start 3xui-dual-renew.service
```

失败会让 systemd 单元标记失败并写入日志，不会自动发邮件或外部通知。续期会短暂重启面板及其 Xray 进程；节点可能短暂重连。不要把 TCP 80 占用或关闭，否则后续续期可能失败。

## 安装失败后

先按错误提示检查云安全组、端口占用、SOCKS5 凭据、REALITY 目标以及日志。修复后运行：

```bash
bash /root/3xui-residential-relay.sh --resume
```

`--resume` 仅用于本脚本尚未完成的部署，会重用已生成的凭据、重建本脚本管理的配置，不重复创建节点。成功部署后拒绝 `--resume`，避免覆盖你在面板中的后续修改。需要改输入内容时，可先用 root 编辑私有 `state.json` 再恢复；保持 JSON 格式正确。不要为了重试直接删除数据库。

常用服务检查：

```bash
systemctl status x-ui
journalctl -u x-ui --no-pager -n 80
```

## 实际限制

- 普通 SOCKS5 不为 VPS 到住宅代理之间的连接增加加密。REALITY 保护客户端到 VPS 这一段；访问 HTTPS 网站时，网站自身的 TLS 仍然保护内容。
- 住宅 TCP/UDP 均走同一个 SOCKS5 出站。UDP 通过真实 DNS 请求检测；上游仅支持 TCP 或 UDP 网络不通时，会提示 UDP 暂未测通，TCP 仍可使用。即使检测未通过也不把 UDP 改走直连。外层 VLESS 使用 TCP，云安全组无需因此开放相同端口的 UDP；服务器出站防火墙需要允许供应商 UDP 中继地址/端口。
- 每个中转连接消耗 VPS 和住宅代理的流量，也增加一段链路；速度由线路和供应商共同决定。
- VPS 公网 IP 变化时需要更新节点链接并重新申请对应 IP 证书。
- 默认关闭面板的独立订阅服务，本版本提供两条节点链接。以后启用订阅时需另外配置 HTTPS。
- 显式设置 REALITY minClientVer=1.8.0，允许旧客户端声明的版本，避免 v2rayN 7.12.7 随包内核因服务端默认版本门槛被拒绝。此设置放宽版本门槛，不保证所有第三方客户端兼容；仍推荐更新客户端。
- 面板采用官方发行包加 systemd 安装；本脚本未安装交互式 `x-ui` 菜单。日常管理通过网页与上述 systemctl 命令。

## 迁移已安装的旧版本

已完成安装的服务器下载新脚本后运行 `bash /root/3xui-residential-relay.sh --migrate`。不要使用 `--resume` 覆盖成功部署。

迁移保留面板账号、证书、节点端口、UUID 和密钥；备份旧路由和原有两个入站，验证失败会尝试恢复。如果进程被强制终止，重新下载同版本脚本并运行 `--rollback-migration`，恢复后再迁移。备份在 `/root/3xui-dual/migration-backup.json`，含凭据，权限 0600。若手动修改的路由无法安全识别，会停止并提示，不会静默覆盖。

迁移后面板中的 `residential-out` 直接显示住宅地址；新增住宅出站时，将对应入站标签绑定到该出站，并让规则涵盖 TCP 和 UDP。默认服务器直连意味着漏配的住宅入站可能走服务器出口，添加后应验证实际出口。


## 重新查看结果

下载最新版安装脚本后，运行 `bash /root/3xui-residential-relay.sh --results`。它只更新结果查看工具、在终端显示登录信息和节点，不改变节点、账号或路由。

终端复制菜单：`python3 /root/3xui-dual/manager.py --copy`。支持 OSC 52 的终端可复制到本机剪贴板；不支持时，直接选中终端结果复制。终端中的文字超链接需要 OSC 8 支持。

## 卸载范围

卸载包括本脚本创建的面板、Xray、数据库、账号和节点配置、证书及申请账户、续期任务、旧转发服务、部署记录、备份、日志和安装临时文件。服务必须先停止；正在安装或检查时请先结束该操作。

系统公共依赖、SSH 配置和原有防火墙规则保留。新版本仅删除自己记录并标记的 UFW 规则；旧版本未记录归属的规则、云安全组规则需自行检查。无法确认属于本项目的现有面板或文件会保留并提示。


## 添加住宅 IP 与中断恢复

下载最新版安装脚本后，运行 `bash /root/3xui-residential-relay.sh --add-residential`。此功能仅用于本脚本已成功安装的服务器，不重装面板、不重新申请证书，也不要求重新填写原住宅代理或面板密码。旧版默认阻断或本机转发配置需要先按前文迁移。

新节点使用独立端口、UUID、REALITY 密钥和出站标签，TCP/UDP 都绑定新住宅代理。先测试住宅 SOCKS5 认证，再通过新节点做服务器本机 VLESS/REALITY 握手和出口检测；UDP 测不通不会阻止已通过 TCP 检测的节点添加。住宅 IP 可以轮换，不要求两次检测出口完全相同。

每次添加前会记录恢复信息。普通失败会尝试删除本次新入站并恢复原路由；若 SSH 断开或进程被强制结束，重新连接后运行：

```bash
bash /root/3xui-residential-relay.sh --rollback-add
```

如果上次添加已经完成，此命令只清理未结束的恢复记录，不删除已成功添加的节点。若中断后又在面板修改了相关配置，脚本会停止自动覆盖，保留现场供排查。恢复后用 `--results` 查看全部节点，再决定是否重新添加。

`--results` 会显示原来的两条节点及后续添加的全部节点；`--copy` 菜单也会包含新增节点。部署记录和恢复信息含住宅代理凭据，保存在原部署目录内，权限为 0600，卸载时随部署目录一并清理。

新增功能会自动处理已启用的 UFW 中属于本次新端口的规则；不会替你操作云厂商安全组。当前遇到正在运行的 firewalld 会在添加前停止并提示。


### 添加时报 JSON 对象类型错误

若旧版添加时提示 `the JSON object must be str, bytes or bytearray, not dict`，这是脚本未兼容面板返回的对象格式，认证信息通过预检后仍可能遇到此错误。重新下载最新版脚本，先运行 `bash /root/3xui-residential-relay.sh --rollback-add`，恢复成功后再运行 `bash /root/3xui-residential-relay.sh --add-residential`。不要使用旧版 manager.py 恢复，也无需卸载原有部署。


### 新增入站在 update 接口被拒绝

旧添加版本把查询返回的整条记录提交给更新接口，其中 `clientStats` 流量统计数组与表单绑定不兼容。新版使用专门的 `setEnable` 接口启用新入站，并读取核对结果。若终端已显示“已撤回本次新增，原有节点配置已恢复”，重新下载最新版后重试 `--add-residential` 即可；无需卸载原有部署。

## 脚本 1.1.0：统一管理入口

新版安装完成或更新管理器后运行：

```bash
3xui-relay
```

已有部署时，无参数运行也会进入菜单；全新服务器仍进入安装向导。若希望更新已有 `manager.py`，先用新脚本运行 `--results`，之后可用 `python3 /root/3xui-dual/manager.py --menu`。

菜单提供查看结果、添加住宅 IP、检查全部节点、替换住宅代理、重命名、删除追加节点、脱敏诊断和中断恢复。仍保留已有命令参数。新增独立参数为 `--edit-residential`、`--rename-residential`、`--delete-residential`、`--diagnostics`、`--rollback-change` 和 `--version`。

替换上游保留节点地址、端口、UUID 和 REALITY 密钥，因此原客户端链接继续可用。改名保留连接参数，但客户端已导入的显示名称不会自动更新。删除仅支持后续追加节点；基础住宅节点是原有安装/迁移的结构组成部分，可替换上游。删除前终端会要求输入 DELETE，并检查是否仍有其他配置引用该出站。

操作会短暂重启代理服务。修改和删除使用私有 `/root/3xui-dual/pending-change.json` 记录，普通失败自动恢复；SSH 中断后可运行 `--rollback-change`。若部署记录或相关面板配置已发生后续修改，恢复会停止以保留现场。状态原子提交后即视为完成，残留恢复文件不会撤销已提交的操作。

删除追加节点不会自动删除防火墙规则：云安全组及原节点端口的 UFW 规则可自行检查清理；脚本记录的 UFW 规则仍会在完整卸载时处理。

`--check` 现在检查原始直连、基础住宅及全部追加住宅节点，单个节点失败会继续检查其他节点，并返回非零退出码；全局路由或面板不可用时会直接停止。结果保存在 `/root/3xui-dual/check-all.json`，包含节点名称和出口地址，不属于脱敏报告。UDP 暂未测通作为单独提示，不判定 TCP 失败。

`--diagnostics` 不进行故障注入，只输出脚本版本、面板目标版本、架构、节点数量、服务/证书状态和待恢复标记。文件 `/root/3xui-dual/diagnostics.json` 不包含 IP、账号、节点名称、链接或原始日志，可用于反馈基础运行情况。

本版本本地测试情况与真实 VPS 测试方法见[开发与测试](开发与测试.md)。

## 1.1.1：新安装文件名与短命令

安装文件统一为 `3xui-residential-relay.sh`，安装完成后只需输入 `3xui-relay`。也支持 `relay --check`、`relay --diagnostics` 等原有参数。

旧服务器下载新脚本后执行 `bash /root/3xui-residential-relay.sh --results`，会更新管理器并创建 `/usr/local/bin/3xui-relay`。此操作不会修改节点、路由或账号。新脚本的 `--menu` 也会安装短命令。若同名命令属于其他程序，脚本保留它并提示使用完整入口。

旧下载文件名作为兼容入口保留，历史部署目录继续使用 `/root/3xui-dual`，保证已有资料和恢复记录可用。卸载仅清理带本项目归属标记的短命令。


### 管理脚本更新（1.1.2 起）

运行 `3xui-relay update`，或进入 `3xui-relay` 选择 9。更新从本仓库 main 解析固定提交，下载 Python 管理器与同提交 SHA256SUMS，校验内容并执行版本启动检查，原子替换前备份旧版。校验失败保留旧版，替换后启动失败自动恢复。校验用于下载完整性，不是独立签名验证。更新不升级 3X-UI，也不改变节点。

需要手动恢复上版管理器时：`cp /root/3xui-dual/manager.previous.py /root/3xui-dual/manager.py`，然后重新输入 `3xui-relay`。此命令仅恢复管理程序，不回滚节点配置。

菜单等待时释放锁；执行选项时重新读取部署记录并加锁。改名仍保留事务恢复记录，仅更新面板备注，不调用 systemctl 重启；面板自身可能重载 Xray。住宅 TCP 成功而 UDP 未测通时仍报告 TCP 可用，不据此断言供应商不支持 UDP。
